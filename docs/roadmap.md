# 研究路线

写于 2026-07-26。方向依据见下方"动机"一节，均为本仓库实测数据，不是文献转述。

## 动机：两个实测事实

**1. MOSI 上单 seed 的波动大于文献里绝大多数"改进"。** LF-LSTM 5 个 seed（42-46，CUDA）的 test MAE 为 0.971 ± 0.039（样本标准差），最好 0.942 / 最差 1.038。而 MMSA `results/result-stat.md` 里相邻模型的差距普遍是 0.01–0.03 MAE。**该榜单相当一部分排序落在噪声内。** MOSI 测试集仅 686 条，一条样本 = 0.146% Acc-2，1% 以内的差距约等于 1σ。

**2. 在这批 2018 年的特征上，音频和视觉几乎不贡献。** LF-LSTM 模态消融（3 seed）：

| 模态 | MAE ↓ | Corr | Acc-2(non0) | Acc-7 |
|---|---|---|---|---|
| 仅文本 | 0.964±0.015 | 0.652 | 76.7% | 34.2% |
| 仅音频 | 1.447±0.014 | 0.213 | 48.3% | 14.6% |
| 仅视觉 | 1.465±0.011 | 0.070 | 50.3% | 16.6% |
| 音频+视觉 | 1.449±0.024 | 0.147 | 54.9% | 16.9% |
| 三模态 | 0.949±0.006 | 0.648 | 76.9% | 36.2% |

音频/视觉单独使用时 MAE 比恒定预测 0（1.417）还差；加到文本上只买到 0.015 MAE，落在噪声内。

限定：以上出自一个很弱的架构（a/v hidden 仅 32），MulT 的跨模态注意力、Self-MM 的自监督单模态标签能榨出更多。它标定的是信号量级，不是终局结论。

另注意 MMSA 表中 MulT(79.7) → MISA(81.8) → Self-MM(83.4) 这一跳恰好对应"开始微调 BERT"。**编码器强度的收益可能远大于融合结构设计的收益**——这是第 2 阶段要检验的核心假设。

## 与 MMSA 的关系

`/workspace/MMSA`（MIT 协议）。已核对的情况：

- `trains/singleTask/` 14 个文件、2325 行几乎重复的训练循环（`TFN.py` 与 `LMF.py` 名字归一后仅差 14 行）。加模型 = 复制 trainer，训练协议会静默漂移。
- `setup_seed()` 只设 `manual_seed` + cudnn flag，无 `use_deterministic_algorithms`、无 worker 播种——运行非逐比特可复现。
- `data_loader.__truncate` 为死代码，且内部 `do_truncate` 忽略 `length` 参数硬编码 `index:index+20`。
- `config_regression.json` 中 mosi/unaligned 的 `seq_lens` 写作 `[50,500,375]`，实际 pkl 为 audio 375 / vision 500（运行时被数据覆盖，故未致命）。
- `result-stat.md` 全为单值，无方差。

**取用策略**：模型定义可移植（署名 MIT），特征管线与结果表作为复现靶子；训练循环、评测协议、复现性基础设施由本仓库自己实现。**已验证我们的指标实现与其 `metricsTop.py` 逐位一致**（差异仅来自其 round 到 4 位小数），故两边数字可直接对比。

目标不是"做一个更大的框架"。核心保持薄——单一 trainer + 模型注册表，目标 1500 行以内（对比其 6000 行）。

## 第 1 阶段：复现（不可跳过）

移植并复现 5 个跨年代代表 + 1 个关键对照：

按技术演进排序，每一步回答"上一步缺什么"：

| # | 模型 | 解决了什么 | MMSA 报告 MAE / Acc-2(non0) |
|---|---|---|---|
| 1 | EF-LSTM / LF-DNN | 最朴素的早/晚融合，确立下限 | 0.949 / 78.5，0.955 / 78.6 |
| 2 | TFN (2017) | 用外积显式建模模态间交互 | 0.947 / 79.1 |
| 3 | LMF (2018) | 低秩分解，解决 TFN 融合层参数量爆炸 | 0.950 / 79.2 |
| 4 | MFN / Graph-MFN | 引入跨时间的记忆 | 0.927 / 78.9，0.956 / 78.4 |
| 5 | MulT (2019) | 跨模态注意力，直接处理未对齐序列 | 0.880 / 81.0 |
| 6 | MISA (2020) | 模态不变/特有表征解耦 | 0.777 / 83.5 |
| 7 | Self-MM (2021) | 自监督生成单模态标签 | 0.708 / 85.5 |
| 8 | **纯文本微调 BERT** | **对照组** | — |

**第 8 项是这条故事线真正的看点，不是补充。** 上表中 MulT(81.0) → MISA(83.5) → Self-MM(85.5) 这一跳恰好对应"开始微调 BERT"。没有纯文本对照，前七步排出来的只是一张榜单；有了它，才能判断这条故事线讲的是"融合结构在进步"还是"文本编码器在进步"——而后者正是第 2 阶段的核心假设。

### 验收标准（2026-07-26 定，不因单次结果调整）

**参照物是 MMSA 的 `results/result-stat.md`，不是原论文。** 原论文（TFN 2017、MFN 等）用的是 CMU-SDK 的 GloVe 文本特征，部分还用了不同划分；MMSA 把所有模型用统一的 BERT 特征与统一划分重跑过。拿 BERT-特征的结果去比 GloVe-特征的数字，比的是特征不是模型。原论文数字记录在案作为背景，不作为达标目标。

**超参来源**：以 MMSA 对应模型的配置为准（同协议才可比），同时查阅并记录原论文的超参。两者不一致时，差异本身就是排查线索，写进模型文件的 docstring；原论文超参无法确认时明确注明"未能确认"，不臆测。

**判据**：每个模型跑 **10 个 seed（固定 42-51，事先注册）**，取均值，用标准误（SE = σ/√10）度量差距：

| 落后 MMSA 报告值 | 判定 |
|---|---|
| ≤ 1 SE（含更优） | 复现成功 |
| 1–2 SE | 复现成功，但标记待查 |
| > 2 SE | **未复现**，进入查代码循环 |

"不能差太多"需要一个数，而我们自己 seed 的离散度是唯一诚实的标尺——MMSA 报的是单个值，没有方差。MAE 越小越好，其余越大越好。主指标为 MAE 与 Acc-2(non0)，其余一并汇报。

判定由 `scripts/check_acceptance.py` 执行，不靠人工裁量：

```bash
python scripts/check_acceptance.py tfn_mosi      # 单组
python scripts/check_acceptance.py --all         # 全部有参照的组
```

**不达标时的唯一补救手段是检查并完善代码**，直到 10 seed 的整体效果达标为止。明令禁止：

- 挑选 seed（seed 集合事先注册为 42-51，任何情况下不得为达标而更换）
- 为达标而事后调超参（复现阶段一律使用 MMSA 对应模型的超参）
- 只报好看的那个指标

若逐项核对实现后仍不达标，那是一个需要写进 `docs/experiments.md` 的发现（协议差异、或对方数字本身不稳），如实汇报，不得抹平。

**产出**：一张"哪些差距扛得住严格协议"的表。这张表本身就是产出，不只是中间步骤。

其余硬性要求：

- 与纯文本对照组做配对 bootstrap 显著性检验
- 全部运行落盘 `result.json`（超参 + 环境指纹 + git commit + 预测哈希）
- 改动 data/metrics/模型后跑 `scripts/check_invariants.py`
- 新实验进入文档时，必须同时在 `scripts/reproduce_all.sh` 里加一条

## 第 2 阶段：主课题——编码器换代 vs 融合结构

**假设：编码器变强后，融合架构之间的排序会坍缩。**

做法：用 WavLM/Whisper 换音频、VideoMAE/CLIP 换视觉，在**同一批融合架构**上重跑第 1 阶段的全部实验，控制变量只有编码器。

- 证实 → 重要的负面结果，说明社区在融合结构上的投入回报有限
- 证伪 → 说明融合设计确有独立价值，且给出它在什么编码器强度下才显现

两个方向都是真结果。基础设施完全复用第 1 阶段。

## 第 3 阶段：候选（视第 2 阶段结果再定）

- **缺失/带噪模态的鲁棒性**：真实部署问题，远未饱和，MMSA 有 `missingTask/TFR_NET` 可直接对照
- **CH-SIMS v2 的逐模态标注**：可做模态贡献归因，赛道不拥挤

## 数据集

**主数据集换成 MOSEI，MOSI 只做副。** 理由见动机第 1 条——MOSI 测试集太小，判别力不足。本地目前只有 CMU-MOSI，MOSEI 需另行下载。

## 工程基础设施

已完成：

- 设备无关（CUDA / Apple Silicon MPS / CPU），同设备同 seed 逐比特可复现
- 单一 trainer + 模型注册表；加模型不改训练循环
- 多 seed 汇总（样本标准差 ddof=1）
- 四道闸门：`check_data` / `check_invariants` / `check_repro` / `verify_runs`，`bash scripts/check_all.sh` 一次跑完
- 运行落盘 provenance（超参、环境、git commit 与 dirty 标记、预测哈希）；结果产物入库，clone 后可重新审计

后续：配对 bootstrap 显著性检验、跨模型结果汇总表生成。
