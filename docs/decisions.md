## 2026-07-25 基础环境

**PyTorch 用 cu128 轮子。** 当时的 GPU 是 RTX 5070 Ti（Blackwell, sm_120），PyPI 默认的 CUDA 版本没有 sm_120 kernel，会在第一次 CUDA 运算时报 "no kernel image is available"。改用 `--index-url https://download.pytorch.org/whl/cu128`，实测 torch 2.11.0+cu128 正常。

> 2026-08-01 补记：本机已换成 RTX 5080（见 `roadmap.md`「换机器」）。**同属 Blackwell sm_120，这条决定原样成立**，torch 2.11.0+cu128 在新机器上同样正常。

**src layout + editable install。** `pip install -e .` 让 `scripts/` 直接 `import msa`，不用在每个脚本头部塞 `sys.path.insert`。

**特征 NaN 直接置零。** MMSA 的 audio/vision 特征在部分数据集上带 NaN/Inf。本次 MOSI 加载后检查全部 finite，`_clean()` 作为对 MOSEI 等数据集的防御保留。

**评测指标保留两套 Acc-2 口径。** 文献里 MOSI 的二分类准确率有两种算法：`non0`（丢掉 label==0 的中性样本，Zadeh 等）和 `has0`（非负 vs 负，全样本，Yu 等），数值能差 1-2 个点。两个都算，比较时不会对错基线。

**统一使用 `regression_labels` 作为监督信号，不用 `annotations` 字符串。** aligned 与 unaligned 两个 pkl 的 id 顺序、回归标签完全一致，但 `03bSnISJMiM$_$11`（label -0.5）在 aligned 里标为 Neutral、在 unaligned 里标为 Negative——annotations 字段有边界不一致，只作展示用。

**模型选择以 valid MAE 为准，early stopping patience=8。** 与 MMSA 官方基线一致，避免用 test 调参。

## 2026-07-25 设备兼容与复现性

**设备解析集中在 `msa/device.py`，其余模块不出现 `torch.cuda`。** `--device auto` 按 cuda > mps > cpu 选择；显式指定但不可用时抛错而非退回 CPU——静默降级会让计时和显存数据失去意义。`pin_memory` / `non_blocking` 只在 CUDA 上开启，MPS 和 CPU 上是无意义的（MPS 没有 pinned host memory 概念）。

**特征在 Dataset 里就 cast 成 float32。** MMSA 的 audio/vision 存的是 float64，而 MPS 后端不支持 float64，放到 device 上才转换会直接报错。

**打乱用采样器私有的 generator，不用 DataLoader 的 generator。** 踩到的坑：DataLoader 会从自己的 generator 里抽 worker 的 base_seed，抽取次数随 `num_workers` 和 `persistent_workers` 变化，于是 `num_workers=0` 与 `=2` 的打乱顺序不同、结果对不上。改成 `RandomSampler(generator=...)` 后，batch 顺序只是 seed 的函数，实测 0/2/4 workers 哈希一致。

**CPU 线程数是复现性的一部分。** CPU 归约按线程切分，1/4/12 线程给出三份不同结果。`--num-threads` 调 `torch.set_num_threads()` 并覆盖 `OMP_NUM_THREADS`，跨机器对比时必须显式传。

**跨设备类型不追求数值一致。** CUDA / MPS / CPU 的归约顺序与快速数学实现不同，强求一致意味着放弃全部硬件加速。保证的是"同设备内逐比特可复现"，并把设备写进 run_name 与 `result.json` 的 `env`，避免把不同设备的数字混进同一张表。

**每次运行落盘预测哈希。** `result.json` 里的 `test_pred_sha256_16` 是判断两次实验是否真的等价的最短路径——指标相同不代表预测相同。

## 2026-07-26 代码审查

**序列编码按真实长度取末状态，而不是 `h[-1]`。** aligned_50 里 70.4% 的步是 padding，且 BERT 对 `[PAD]` 输出的嵌入非零，audio/vision 虽是零填充但零输入同样会推动 LSTM 状态演化。改为用 `attention_mask` 长度 gather 最后一个真实步的输出。**这不是精度优化**：5 seed 消融显示掩码版反而略差（MAE 0.971 vs 0.954，约 0.5 个标准差，unaligned 上同样持平）。留它的理由是语义正确、对 padding 长度不变；旧行为保留为 `--ignore-lengths` 供对照。数据见 `docs/experiments.md`。

**aligned 模式下三个模态共用文本长度。** 已全量核对：aligned_50 中每个样本在 `attention_mask` 长度之后的 audio/vision 帧严格为零，说明它们与文本共享同一条词级时间轴。unaligned 模式则各用自己的 `audio_lengths` / `vision_lengths`。

**pkl 的 `classification_labels` 不用。** 它是 `sign(regression)+1` 的 3 分类（0/1/2 = 负/恰好零/正），与我们按四舍五入推导的 7 分类 `label_7` 不是一回事，名字容易误导。监督信号统一用 `regression_labels`。

**特征缓存按 resolve 后的路径做键。** `lru_cache` 直接以入参为键时，同一个文件用 `Path` 和 `str` 各传一次就会缓存两份 ~400MB 的 pickle。

**不变量检查固化成 `scripts/check_invariants.py`。** 指标实现、标签口径、padding 约定、掩码正确性、评测顺序、缓存行为、平凡预测下界——改动 `data`/`metrics`/模型后跑一次，退出码非零即回归。

## 2026-07-26 单一 trainer + 模型注册表

**一个训练循环服务所有模型。** MMSA 的 `trains/singleTask/` 是 14 个文件、2325 行几乎重复的 trainer（`TFN.py` 与 `LMF.py` 名字归一后仅差 14 行）——这正是各模型评测协议静默漂移的来源。这里模型只通过 `MSAModel` 契约定制行为，其余（选择指标、early stopping、checkpoint、provenance）全部共享，因此天然可比。

**模型契约刻意收窄成三件事**：`forward(batch) -> {"M": ...}`（键 `M` 必需）、`compute_loss`（默认 L1，多任务模型覆写）、`param_groups`（微调文本编码器时要更小的学习率）。trainer 对模型内部一无所知，加模型不需要碰 trainer。

**注册表用惰性导入。** `registry` 在模块层导入 `models` 会与"模型 import registry 来注册自己"形成循环，所以 `issubclass` 检查放在装饰器内部，`available_models()` 触发一次 `import msa.models`。

**重构以预测哈希验收。** LF-LSTM 默认路径重构前后哈希均为 `172967c7dced83b2`，5 seed 汇总也与重构前手工循环的数字逐位一致（MAE 0.9708±0.0346）——证明这次重构没有改变任何数值。这是重构该有的验收方式。

**多 seed 是 CLI 的默认形态。** `--seeds` 接受多个值并直接输出 mean/std/min/max；只给一个 seed 时会打印警告。理由见 `docs/roadmap.md` 动机第 1 条。

**输出目录改为 `outputs/<model>_<dataset>_<device>/seed<N>/` + 同级 `summary.json`。** 第 1 阶段要跑 6 个模型 × 5 seed × 多数据集，扁平命名撑不住。

## 2026-07-26 复现口径加固与可审计性

**汇总用样本标准差（ddof=1），不是 numpy 默认的 ddof=0。** 我们报的是"再跑几个 seed 会有多大波动"的估计，ddof=0 在 n=5 时低估 11%。本项目的核心论点正是拿这个波动去比对已发表的差距，所以低估等于把论点做强——必须用无偏估计。已按新口径重算全部记录（均值不变，仅 std 变大）。

**指标实现改为逐行对齐 MMSA 的 `metricsTop.py`。** Acc-7/Acc-5 改为「先 clip 后 round」的原顺序（与原先的「先 round 后 clip」在 20 万个点含全部 .5 边界上完全等价，已验证），便于两份实现逐行对读。新增 Acc-5，使可对比的列更多。

**`corr` 在任一侧恒定时返回 0 而非 NaN。** 原先只守卫了预测一侧；真值恒定同样会让 `np.corrcoef` 返回 NaN，而一个 NaN 会污染整组 seed 的均值。

**运行记录里写入 git commit 与 dirty 标记。** 没有这个，一个数字出自哪份代码就无法还原。`scripts/verify_runs.py` 把 dirty 列为警告而非错误——用未提交代码做实验是正常的，但**进入文档的数字必须来自干净工作树**。

**新增 `scripts/verify_runs.py`：从落盘预测重算全部指标、校验哈希、重新推导 summary。** 它能抓住两类事故：产物损坏，以及"改了指标或汇总口径却没重跑实验"。后者是复现性事故里最隐蔽的一种。

**`--select-on` 与 `TrainConfig` 参数在构造时即校验。** 拼错的指标名过去要等到第一个 epoch 结束才炸在 KeyError 上。

**训练损失按样本数加权。** 最后一个 batch 通常不满，按 batch 平均会过度加权它。MMSA 用于选模型的 `Loss` 正是按 batch 平均的——这是我们与其协议之间一处细微但真实的差异，记录在此以免日后误判为复现失败。

**`fit()` 在没有任何 epoch 产生可用分数时明确报错**，而不是让 `torch.load` 抛出令人费解的文件缺失。

## [2026-07-26] 验收标准用标准误分级，参照 MMSA 表而非原论文

背景：要求"复现不能比 MMSA / 原文差太多"，但"差太多"需要一个可执行的界线，且 MMSA 只报单个数字、没有方差。

选项：A 严格不低于报告值 / B 差距 ≤ 1 SE 视为通过 / C 按 SE 倍数分级（≤1 通过，1-2 标记待查，>2 未复现）

裁定：C，判定由 `scripts/check_acceptance.py` 执行。参照物用 MMSA 的 `result-stat.md`，原论文超参查阅记录但不作达标目标。

依据：我们自己 seed 的离散度是唯一诚实的标尺。TFN 的 MAE 差 0.0005（0.02 SE）去追毫无意义，而 Acc-2 差 4 SE 则确实指向问题——分级判据能区分这两种情况。参照原论文不可行：TFN(2017) 等用的是 CMU-SDK 的 GloVe 特征、部分还用了不同划分，比的是特征不是模型。

已否决：A —— 会诱导挑 seed 和事后调参凑数，而这正是本项目路线图批评的做法；B —— 单一阈值无法区分"值得看一眼"和"真有问题"。

复查条件：换到 MOSEI（训练集大 12 倍，σ 会明显变小）后，SE 阈值对应的绝对差距会收紧，届时需确认阈值是否仍合理。

## [2026-07-26] TFN 采纳不裁剪梯度、放开轮数上限

背景：TFN 10 seed 验收判定 Acc-2 低 4.3 SE，排查实现差异。

选项：A 保持我们的默认（裁剪 1.0、上限 40 轮）/ B 对齐 MMSA 的 trainer 行为

裁定：B。验收组改为 `--grad-clip 0 --epochs 200`。

依据：MMSA 的 trainer 完全不做梯度裁剪，且用 `while True` + patience 无轮数上限。改为不裁剪后 MAE 由 0.9585 → 0.9546（+1.0 SE → +0.8 SE，转为通过）；轮数上限在 10 个 seed 中仅影响 seed 50，但同属实现差异，一并消除。

已否决：A —— 复现阶段的目标是消除实现差异，我们的默认值再合理也不该带进参照对比。注意这两项只在**复现组**对齐；自建模型仍用我们的默认。

复查条件：若某个后续模型在不裁剪下发散，则该模型需单独记录并保留裁剪，不适用本条。

## [2026-07-26] TFN 的 Acc-2 差距归因于参照值的测试集选择偏差，不再追平

背景：排除七项假设后，TFN 的 Acc-2/Corr 仍低约 4 SE，而 MAE/Acc-7/Acc-5 打平。

选项：A 继续查实现 / B 在测试集上调参追平 / C 归因于参照值本身并记录

裁定：C。裁定写入 `docs/acceptance_status.json`，`check_acceptance.py` 按 `gap_explained` 处理。

依据：`MMSA/src/MMSA/run.py` 第 267-270 行，调参分支用 `do_test(dataloader['test'])` 评估候选配置，用验证集的那行被注释掉；而 `config_regression.json` 中 TFN 的每项超参都落在 `config_tune.json` 的搜索空间内。故其数字是"按测试集选出的超参在测试集上的成绩"。完整排查见 `docs/investigations.md#tfn-acc2`。

已否决：B —— 那等于把对方的方法论缺陷一起继承，与本项目的全部前提冲突；A —— 七项假设已逐一排除，继续查的边际收益低于把偏差量化（已列入待办）。

复查条件：若后续某个模型出现同样模式（Acc-2/Corr 低而 MAE/Acc-7 打平），**不得直接套用本条**，必须给出该模型自己的排查记录后再引用。

## [2026-07-28] 主指标改为 MAE + Corr，Acc-2 降级为汇报项

背景：Acc-2 作为主指标的粒度不足以支撑判据要求的精度。non0 口径在 656 个测试样本上计算，**1 个样本 = 0.152 个百分点**；has0 在 686 个上算，1 个样本 = 0.146。而判据要分辨的差距是 0.6–1.3 个百分点，即 **4–8 个样本**。同时它只看符号、丢弃全部幅度信息，而 |真值| < 0.5 的样本符号近乎随机（实测符号错误率 62%，且三个模型一致）。

选项：A 维持 MAE + Acc-2(non0) / B 改为 MAE + Corr / C 改为 MAE 单指标 / D 改为 MAE + Acc-7

裁定：**B**。`check_acceptance.py` 的 `PRIMARY = ("mae", "corr")`，Acc-2/Acc-5/Acc-7/F1 全部照常汇报但不参与判定。

依据：MAE 与 Corr 是仅有的两个连续指标，其余四个都被样本数量化。两者互补——MAE 抓校准，Corr 抓排序。Acc-7 虽比 Acc-2 细，仍以 1/686 量化，且 7 个桶的边界本身是人为的。

**已知弱点，记录在此以免被误用**：Corr 对尺度与平移不变，一个把预测整体放大十倍的模型 Corr 不变。它单独不足以判定回归质量，**必须与 MAE 同时看**，这也是不采纳 C（MAE 单指标）之外的另一半理由。

### 这次变更改变了已有判定，必须留痕

| 组 | 旧（MAE+Acc-2） | 新（MAE+Corr） |
|---|---|---|
| TFN | 通过（标记） | **未达标**（Corr +4.3 SE） |
| EF-LSTM | 通过（标记） | **未达标**（Corr +2.8 SE） |
| MISA | 未达标 | **通过**（Corr +0.9 SE） |
| LMF | 通过（标记） | 通过（Corr −4.4 SE，优于 MMSA） |

通过数由 6 降到 5，**整体更严**。MISA 由未达标转为通过是这次变更的直接后果，在此明确记录，不得在后续叙述中略去。

**为什么这不算"事后调整判据以迎合结果"**：论据（Acc-2 的量化粒度与丢弃幅度）不依赖于任何一组结果，且变更代价是两个模型新增未达标。但时点确实在看到结果之后，所以此处如实标注该风险，并保留旧判定于表中供审计。

复查条件：换到 MOSEI（测试集 4659 条，Acc-2 的量化粒度降到 0.021 个百分点）后，该理由的强度大幅下降，届时应重新评估是否让 Acc-2 回到主指标。

## [2026-07-28] 参照标准限定为权威公开来源，且逐条标注出处

背景：一次归因错误——曾据"已发表的 BERT 基线 LMF Acc-2 82.5"判断我们落后 3.9 个百分点，核对后发现该数字是三手转引（Self-MM 论文 → MISA 论文 → Sun et al. 2019），而 MISA 论文自己跑的 LMF 是 76.4。同一模型同一数据集，文献跨度：TFN 的 MOSI MAE **0.901–0.970**，LMF 的 Acc-2 **76.4–82.5**。检索还会返回明显不可信的数字（有论文声称 MOSEI 上 7 分类准确率 97.87%，而真实前沿约 54%）。

裁定：

1. **验收参照物只能是**：MMSA 这类同协议重跑全部模型的公开框架，或**原作者论文中由其本人跑出的数字**。
2. **转引数字（论文 A 引论文 B 的表）一律不作参照**，只可作背景，且必须标注完整引用链。
3. `docs/paper_reference_mosi.json` 的每条记录必须包含：**谁跑的 / 什么特征 / 转引自哪里**。来源冲突时**两条都记，不挑一个**。
4. 越过 MMSA 覆盖范围（CENET 2022 / TETFN 2023）之后，新模型的参照物按第 1 条取原作者论文数字，**且必须同时记录其特征与划分**；特征不同则只能作背景，不能进判据。

依据：判据的可信度不高于其参照物的可信度。今天这次错误的根源正是引用了一个没有标注出处的数字。

## [2026-07-30] SE 判据加一个绝对差地板：噪声地板

背景：判据以**我们自己的方差**为单位度量差距，而方差跨模型相差 **29 倍**（σ(MAE) 从 EF-LSTM 的 0.2095 到 Self-MM 的 0.0072）。后果是同一个绝对差的判定完全不同：

| 绝对差 0.011 MAE 落在 | SE 倍数 |
|---|---|
| EF-LSTM (σ=0.2095) | +0.2（轻松通过） |
| Self-MM (σ=0.0072) | +4.8（严重未达标） |

而实际数据里，**EF-LSTM 的绝对差是 Self-MM 的 20 倍（0.1229 vs 0.0062），却是前者"通过（标记）"、后者"未达标"**。判据在移植质量最好的地方最严苛——σ 随模型变强而收缩。

选项：A 双条件（SE>2 **且** 绝对差 > 噪声地板）/ B 判定不变，只强制并列绝对差 / C 不改，把偏严作为诚实代价记录

裁定：**A**。`check_acceptance.py` 新增 `NOISE_FLOOR`，超过 2 SE 但绝对差小于噪声地板时判 `pass*`，不计为失败。

**阈值不是新选的**：噪声地板取 LF-LSTM 基线在 seed 42-46 上的样本标准差，**该数字在 `roadmap.md` 开篇的立论里就已注册**（"单 seed 的 MAE 波动大于文献里绝大多数改进"），远早于任何验收运行。MAE 0.0387、Corr 0.0110、Acc-2(non0) 0.0124、Acc-7 0.0262。逻辑是：**小于重跑一次就会产生的波动的差距，不可能构成"移植失败"的证据。**

### 这次变更改变了哪些判定

| 组 | 旧 | 新 |
|---|---|---|
| MulT | 未达标 | **通过**（MAE 0.0175、Corr 0.0105 均低于地板） |
| CENET | 未达标 | **通过**（MAE 0.0110、Corr 0.0046） |
| Self-MM | 未达标 | **通过**（MAE 0.0062） |
| TFN | 未达标 | 未达标（Corr 0.0131 > 地板 0.0110） |
| EF-LSTM | 未达标 | 未达标（Corr 0.0409 > 地板） |

由 5 通过 / 4 未达标变为 **8 通过 / 2 未达标**。**这是一次纯粹的放松**，四组从失败转为通过——必须明确记录，不得在后续叙述中略去。

**边缘警告**：MulT 的 Corr 缺口 0.0105 与地板 0.0110 只差 0.0005。这一项的"通过"极度勉强，不应被引用为"MulT 复现良好"。

### 这条规则不修的方向（必须一起读）

地板只挡"差距小但 SE 大"，**不挡"差距大但 SE 小"**。EF-LSTM 的 MAE 绝对差 0.1229 是地板的 **3.2 倍**、F1 是 **8.9 倍**，却因崩溃 seed 把 σ 抬到 0.2095 而只有 +1.9 SE——A 之下它在这些指标上仍算"标记"。

因此 `check_acceptance.py` 对这种情况**逐指标显式报警**（"our own seed spread is wide enough to hide it… Treat it as a gap to investigate, not as a pass"）。判据没修的东西，至少不能让它静默通过。

**待办**：稳健性维度（中位数判据，或崩溃 seed 数上限）仍未实现，那才是修第二个方向的正解。

复查条件：换到 MOSEI 后噪声地板会明显下降（训练集大 12 倍），必须重新测量 LF-LSTM 在 MOSEI 上的 σ 并替换，**不得沿用 MOSI 的数字**。

## [2026-07-31] SE 的分母封顶：离散度可让检验更严，不可更松

背景：判据以模型自身的 σ 度量差距，于是**不稳定的实现会因为不稳定而获得更宽的容差**。EF-LSTM 的两个崩溃 seed 把 σ(MAE) 从约 0.03 撑到 **0.2095**，于是一个 **3.2 倍噪声地板**的缺口（绝对差 0.1229）只算 **+1.9 SE**，判为"标记，不阻塞"。

这与 2026-07-30 加的噪声地板是**同一问题的两个方向**：地板挡"差距小但 σ 紧"，此处要挡"差距大但 σ 松"。`#ef-lstm-collapse` 与 `#corr-gaps` 早已指出方向，一直未实现。

选项：A 绝对差上限（超过 N 倍地板即失败）/ B **SE 分母封顶** `min(σ_模型, σ_基线)` / C 改用中位数 / D 崩溃 seed 数上限

裁定：**B**。`check_acceptance.py` 计算 SE 时用 `min(sd, NOISE_FLOOR[metric])`，被封顶的行在输出里标 `[sd capped]`。

依据：

1. **用的是同一个锚**，不引入新常数。A 需要选一个 N，C、D 需要选阈值——都会变成"事后挑的数"。
2. **语义清楚且对称**：地板说"小于重跑波动的差距不算失败"，封顶说"大于基线噪声的离散度不换来豁免"。两条共用 `NOISE_FLOOR`（LF-LSTM 在 seed 42-46 上的样本标准差，roadmap 开篇即注册）。
3. **只在 σ 超过基线时起作用**，稳定模型完全不受影响。

### 这次变更改变了哪些判定

| 组 | 指标 | 旧 | 新 |
|---|---|---|---|
| EF-LSTM | MAE | 标记（+1.9 SE） | **未达标（+10.0 SE）** |
| EF-LSTM | Corr | 未达标（+2.8） | 未达标（+11.7） |
| MFN | Corr | 标记（+1.1） | 通过\*（+2.3，但差 0.0078 < 地板 0.0110） |

**这是一次收紧**，与 07-28、07-30 两次放松相反。EF-LSTM 的 MAE 因此新增为失败项，其裁定条目已同步更新（归因不变：崩溃率是两份实现共有的配置性质）。

全表共 25 个指标行被封顶，绝大多数是 EF-LSTM 的。

### 保留的探针

`masked` 报警（"绝对差超地板却被宽方差藏住"）在封顶后理论上不可达，**故意保留**：若它再次触发，说明封顶有漏洞。

复查条件：换 MOSEI 后 `NOISE_FLOOR` 必须重新测量（训练集大 12 倍，基线 σ 会明显下降），**封顶与地板都依赖它，不得沿用 MOSI 的数字**。

## 2026-07-31：参照自带方差时，用两样本 SE

**背景**：BERT-MAG、MMIM、ALMT 三个模型，MMSA 的 `result-stat.md` **一个都没有**。查了全表，确认不是遗漏而是它压根没登记这三个。

所以对它们而言不存在"MMSA 公开声称的数字"可比。替代方案是**跑 MMSA 自己的代码**取参照——同样的十个 seed（42-51）、同样的 MOSI pickle、它自己的默认超参。

**这不是退而求其次，而是更强的参照**：公开表是无方差的单值，而自跑结果带 σ。比较从"点 vs 分布"变成"分布 vs 分布"。

**判据相应修改**（`scripts/check_acceptance.py:standard_error`）：

```
SE = sqrt( cap(σ_ours)² / n_ours  +  cap(σ_ref)² / n_ref )
```

两侧的 σ 都先按噪声地板封顶，理由与 07-31 那条相同——**不稳定不该换来宽容，这对参照和对我们一视同仁**。

对 MMSA 公开表的十一个模型，`σ_ref` 不存在，公式退化为原来的 `σ/√n`，**判决逐条不变**（已回归验证：11 个 VERDICT 全部一致，0 失败）。

**这是一次放宽**，因此必须说清楚定这条规则的时点：**三个模型我们自己一次都还没跑**。规则先立，数字后出——否则就是看着结果调判据，正是本项目反复禁止的事。

**参照性质的警告**（已写进 `docs/mmsa_code_runs_mosi.json` 的 `caveat`）：这是 MMSA 实现的数字。**凡 MMSA 偏离原论文之处，这份参照一并继承了偏离**（CLAUDE.md 第 5 条）。因此这三个模型各自仍欠一份与原论文的对照，不能拿"追平 MMSA 自跑值"当作复现完成。

## [2026-07-31] 跨模型聚合判据：先定义"打平"，再去测量

**背景**：`#systematic-bias`（2026-07-27）留下的待办，一直没做。逐模型判据每组差 0.5–1.5 SE、逐个判"通过"，聚合起来却是符号检验 p≈3×10⁻³ 的一致方向。**判据在结构上看不见它**——它问的是"这一个模型复现了吗"，而系统性偏置只在跨模型层面存在。

现在要回答的是一个更高层的问题："我们这套实现整体上是否已经与公开基准打平"。这个问题此前没有判据，**必须在看数字之前把它定死**。

**选项**：A 收紧逐模型阈值（1 SE → 0.5 SE）/ B 加一个跨模型聚合检验，与逐模型判据并存 / C 分层随机效应模型（meta-analysis）估总体偏移量

**裁定：B。**

### 判据的完整定义

对象：全部有参照值的复现模型。主指标 **MAE、Corr** 各自独立计算（沿用 2026-07-28 的主指标裁定）。

两个统计量：

1. **符号检验**——k 个模型中"我们更差"的个数，双侧二项检验。只看方向，对量级不敏感，也因此不受任何单个模型的异常值主导。
2. **Stouffer 合并 z**——`z_i = shortfall_i / SE_i`（正 = 我们更差），`Z = Σz_i / √k`，双侧正态。SE **沿用 `check_acceptance.py:standard_error` 的定义**（含噪声地板封顶与两样本合并），保持全项目一套口径。

**聚合检验不套噪声地板。** 地板是逐模型判定里"不计为失败"的豁免；聚合检验问的是方向的一致性，把小于地板的偏差抹成零会把待检验的信号本身删掉。

**判定**：

| 条件 | 结论 |
|---|---|
| Z 显著为负（p<0.05） | **超过** |
| 两个检验均不显著（p≥0.05） | **打平** |
| 任一检验显著为正 | **系统性落后** |

**敏感性附注**：同时报一份剔除 EF-LSTM 后的值（它的崩溃 seed 会主导 z 的量级）。**这是附注，不参与判定**——先声明，是为了堵住"看完结果再挑样本"的路。

### 必须与结论同读的限定

- **各模型不独立**。同一个 686 条测试集、同一份 2018 年特征、同一套训练协议，偏差正相关。Stouffer 假设独立，于是**低估方差、p 偏小**。方向是：判"落后"偏激进，判"打平"偏保守——**Z 不显著时结论稳，显著时不能直接读作"每个模型都差"**。
- **参照 A（MMSA 公开表）是单值**，其自身抽样误差不可知，公式退化为 σ_ours/√n，等于假定表是精确的。而 `#mmsa-all-eleven` 已证 **9/11 个模型它自己的代码达不到那张表**。所以对表的"系统性落后"**不可直接读作我们的实现缺陷**。
- **参照 B（我们跑的 MMSA 代码）目前 n=5**，且其 sd 出自 MMSA 的 `np.std`（ddof=0），与我们的 ddof=1 不同口径，需换算后才可比。

**已否决**：

- **A（收紧逐模型阈值）**：把"单模型噪声"与"跨模型系统性"混为一谈，且要重新裁定全部已通过项——那是事后调判据，本项目反复禁止。
- **C（随机效应模型）**：需要每个模型的逐 seed 配对数据，参照侧现在只有 n=5 的汇总值。**等参照补到逐 seed 后再做**，届时应改用配对检验，功效远高于两样本。

**复查条件**：参照侧补齐逐 seed 之后（配对检验取代两样本）；换 MOSEI 之后（`NOISE_FLOOR` 必须重测，SE 定义随之变）。

### 后续修正（2026-07-31，同日）：配对检验的前提不成立，不改

上面写了"参照补到逐 seed 后应改用配对检验，功效远高于两样本"。**这句是错的**，在有数据可查之前就不该那么写。

拿已有 10 seed 的四个模型，算同一个 seed 在两份实现之间的相关系数：

| | MAE | Corr |
|---|---|---|
| EF-LSTM | −0.174 | −0.424 |
| ALMT | +0.000 | +0.316 |
| BERT-MAG | +0.089 | +0.321 |
| MMIM | +0.119 | +0.119 |

**围绕 0，方向都不一致。** 原因不难想：seed 只决定 RNG 流的起点，两份实现消耗随机数的顺序和数量完全不同，所以"同 seed"在两边并不意味着同一次抽样。配对检验的功效来自配对内相关，这里没有相关可用，强行配对只会白丢自由度。

**裁定：维持两样本（Welch 形式，方差相加），即 `standard_error` 现有的做法。** 逐 seed 数据的价值不在配对，而在于（a）能按 ddof=1 算出参照的方差，（b）能把参照的 n 从 5 提到 10 从而收紧 SE。

**这条也是给下一个人的提醒**：把"应该用更好的方法 X"写进复查条件时，先确认 X 的前提在这份数据上成立。

### 2026-09-04 对比损失的筛选判据是验证集指标，不是损失值

背景：第 2 阶段的任务书写「逐一跑通后仅保留损失值低于现有交叉熵损失的候选项」。这条判据在本项目里无法执行，也无法解释。

三个理由，任一单独成立即足够：

1. **本仓库没有交叉熵。** `models/base.py` 的默认损失是 L1，MISA/ALMT 用 MSE，标签是 `[-3,3]` 连续值。`acc7` 是回归输出事后分箱得到的，不是分类头输出。
2. **不同损失的数值不可比。** InfoNCE 的 0.4 与 L1 的 0.9 之间没有大小关系——量纲、最小值都不同，且随 batch size 与温度漂移。按数值排序等于按归一化常数排序。
3. **对比损失不是任务损失的替代品。** InfoNCE 单独训练产生不了情感分数，它与任务损失是相加关系。「逐一跑通、只留比 CE 低的」没有对应的实验可做。

选项：A 按损失值筛（任务书原文）／B 按验证集 MAE/Corr 筛／C 两者都记录

裁定：**B，并把各候选的损失曲线逐 epoch 落盘**（C 的记录部分保留，因为后面的梯度变化率调权与交叉点判断需要这些曲线）。

依据：文献里的通行做法就是 B——MMIM（EMNLP 2021）、MISA（MM 2020）把 InfoNCE / CMD 作为辅助项，消融表报 MAE/Corr/Acc/F1；SimCLR / SupCon / BYOL / VICReg 用下游 linear probe 准确率评价。**其中 MMIM 与 MISA 就在本仓库里，当初都是按 MAE/Corr 验收的。** 多损失加权同样有通行做法：GradNorm（2018）按梯度范数平衡、不确定性加权（Kendall 2018）按方差平衡，两者都先拉平量纲。

已否决：A——理由见上三条。C 作为唯一判据——损失曲线能回答「什么时候出现交叉点」，回答不了「哪个对最终指标有用」。

复查条件：若后续引入的目标函数与任务损失同量纲、且单独就能产生预测（例如换成另一个回归损失而非辅助项），那时数值比较才有定义。

### 2026-09-04 筛选判据加多重比较校正与效应量地板

背景：第一版判据是「在任一指标上超过对照组 1 个标准误即保留」。它在第一轮 14 候选上保留了 4 个。

依据（这是判据被推翻的直接证据）：单侧 1-SE 阈值在零假设下通过概率 0.159，两个指标任一通过即保留 → 每候选约 0.29，14 个候选的**期望保留数 4.1**。实际保留 4。且这 4 个各自都是「一个指标勉强过线、另一个为负」，`triplet` 的 Corr +1.06σ 伴随 MAE −0.81σ。这个输出与噪声不可区分。

裁定：改为三条同时满足——

1. Welch 单侧 t 检验，**Benjamini-Hochberg q=0.10** 跨全部 (候选 × λ × 指标) 校正。用 FDR 而非 Bonferroni，因为这是初筛：假阳性的代价是一次多余的确认实验，不是一个错误的公开结论。
2. **效应量地板** 0.01 MAE 或 0.01 Corr（约对照组 seed 标准差的一半）。小于此的效应即使显著也无法支撑后续的组合步骤。
3. **不允许拿一个指标换另一个**：未过线的那个指标不得比对照组差出 1 个标准误以上。

用不配对检验，尽管对照与候选共用 seed 42-46：加一项损失会改变整条轨迹。**实测 seed 相关性中位数 −0.00、范围 −0.91…+0.86**，配对前提不成立——与第 1 阶段跨实现那次同样的结论（`roadmap.md` 里「撤回改用配对检验」那条）。相关性作为诊断量逐轮输出，而不是被假定。

已否决：Bonferroni（初筛阶段过严，会把 λ 扫描的全部结果压成零）；提高 seed 数到 10（能把标准误降 √2 倍，但当前最大效应量只有 1.2σ，降标准误改变不了结论，且成本翻倍）；维持 1-SE 阈值（见上）。

复查条件：**这条判据在 λ 扫描的数据被查看之前定稿，其后不得再改。** 若要改，必须先记录新判据、再重跑，不得在既有结果上换判据。

### 2026-09-04 分类线自成一套对照组

背景：第 2 阶段两条线并行（回归 L1 + 分类头 CE）。加了 7 类分类头之后，`acc7` 的含义从「回归输出分箱」变成「分类头 argmax」。

裁定：**分类线只做内部对比**——分类头 + CE 作为它自己的对照组，数字不与回归线并列。

依据：两个 `acc7` 的生成机制不同，并列会被读成可比。现有 14 个模型的参照值全部建立在回归口径上，在分类线上一个都用不上。

已否决：让分类头算期望值 `Σ p·bin` 从而报 MAE/Corr——机制仍与回归线不同，会制造一个看起来可比、实际不可比的数字，正是本条要避免的。

复查条件：若将来把分类头作为主口径（而非对照），需要重立一套参照值，届时这条作废。


### 2026-09-04 初筛冻结，组合项按排名规则选而不按显著性

背景：λ 扫描 140 个检验在 BH q=0.10 下拒绝 0 个。但那个设计的最小可检出效应是 0.0759 MAE（无校正也有 0.0369），实测最大效应 0.0174——**判据没有检出能力，且这在跑之前就可算**。详见 [`investigations.md#screen-underpowered`](investigations.md#screen-underpowered)。

选项：A 加 seed 把初筛做到有功效（要约 70 seed/臂 × 71 组，不可行）／B 放松阈值（无效——无校正也检不出）／C 冻结初筛，组合项按明说的规则选，把 seed 预算花在自适应权重的比较上

裁定：**C。**

组合项的选择规则，机械执行、不涉及显著性：

1. 每个候选在每个 λ、每个指标上排名，取**全网格平均排名**。用全网格而不是各自最佳 λ——`rnc` 是整个扫描里最好的单格（λ=0.03）却在 λ=0.1 上是最差的两个之一，按最佳格选会把这个噪声直接带进组合。
2. 三个机制族系（跨模态 / 无负样本 / 标签相关）各取平均排名最好的一个，保证组合测的是三个不同想法而不是一个想法的三种拼法。
3. 第四个位置给剩余里平均排名最好的。四是任务书设的上限。
4. 组合的 λ 取「所选四项平均排名最好」的那个。

执行结果：**hcl / infonce / simsiam / supcon，λ=0.1**，`linear_ramp` 偏向 `infonce`（四项里排名最好）。`rnc` 平均排名第 6，被规则 1 挡在外面——这正是它要挡的。

依据：任务书写的是「优先选取损失值最低的 1-3 项纳入组合」，没有要求统计显著。而初筛既然无法分辨这些候选，声称「选了显著的那些」会是所有选项里最差的一个。

已否决：A（成本不可行）；B（诊断错误——问题是样本量不是阈值）；按各自最佳 λ 选（见规则 1 的理由）。

复查条件：**这是一次选择，不是一个发现。** 没有任何断言说这四项就是有效的那四项。若换数据集（MOSEI）后初筛具备功效，这个选择应当作废重做。

### 2026-09-04 自适应权重实验：五臂，20 个全新 seed

背景：任务书真正问的是「自适应权重是否优于固定权重」。这个问题**不要求组合里每一项各自显著有益**——它比的是权重规则，不是损失项。

裁定：五臂，各 **seeds 100-119（20 个）**，其余协议与初筛完全一致（TFN、`--unaligned --lr 1e-3 --weight-decay 0`、epochs 40、patience 8）。

| 臂 | 内容 |
|---|---|
| `weight_control` | 纯 L1，无对比项 |
| `weight_equal` | 固定 1/4 —— **对照** |
| `weight_grad10` | `grad_rate`，窗口 10（任务书原文） |
| `weight_grad5` | `grad_rate`，窗口 5 |
| `weight_ramp` | `linear_ramp` 偏向 infonce，`end_fraction=0.5` |

依据与三个设计决定：

- **20 个 seed**：把差值标准误从 0.0134 降到 0.0067，MDE 约 0.019 MAE，覆盖得住实测效应量的量级。成本 5×20 = 100 次运行、约 1.7 小时。
- **全新 seed（100-119，不是 42-46）**：确认阶段不能在挑出候选的同一批数据上做，否则是在自己的选择偏差上盖章。
- **为什么多一个 `window=5` 的臂**：实测 355 次初筛运行的训练轮数中位数是 **24**（只有 9% 跑满 40，70% 到 20，100% 到 10）。窗口 10 意味着**中位数的 run 只有 1-2 次调权机会**——任务书写「每 10 轮」大概假设了更长的训练。没有这个臂，「规则无效」和「规则没机会执行」分不开。窗口 5 给中位数的 run 约 4 次机会。
- **`linear_ramp` 的 `end_fraction=0.5`**：斜坡在第 20 轮走完（70% 的 run 能到），否则按 40 轮铺、中位数只走到 60%，那一臂会退化成 `equal`。

已否决：加长训练（epochs 60 / patience 15）让两个策略有更多空间——会使协议与初筛不可比，且把成本再翻倍；改用配对检验（实测 seed 相关性中位数 +0.12、范围 −0.99…+0.98，前提不成立）。

复查条件：**本设计在任何一次运行之前定稿。** 主判据是 `weight_grad10` / `weight_grad5` / `weight_ramp` 各自对 `weight_equal` 的验证集 MAE 与 Corr，Welch 单侧 + BH（6 个检验）。`weight_control` 不是主判据的一部分，它回答的是另一个问题——组合本身有没有用。


### 2026-09-04 「组合优于纯 L1」用第三批独立 seed 确认

背景：五臂实验的**次要**观测——四项固定均等加权组合对纯 L1，Δ=+0.0131 MAE（p=0.045 单侧）、+0.0088 Corr（p=0.027），Cohen's d 约 0.55-0.63。这不是主判据的一部分，是事后检验的，也没过主判据那道 BH。

选项：A 就此当结论写进去／B 用第三批独立 seed 确认／C 放弃不追

裁定：**B。**

设计（在任何一次运行之前定稿）：

- 只两臂：`confirm_combo`（hcl+infonce+simsiam+supcon，equal，λ=0.1）与 `confirm_l1`（纯 L1）。
- **seeds 120-139**，与 42-46（挑组合项）和 100-119（五臂实验）都不重叠。
- 只两个指标、共 **2 个检验**，Welch 单侧 + BH q=0.10。其余协议不变。
- 成本 2×20 = 40 次运行，约 40 分钟。

依据：这条线索的效应量（d≈0.55）在 n=20 下 MDE 是 0.0133，与观测到的 0.0131 几乎重合——**恰好在检出边缘**，这正是最需要独立重复的位置。而 A 会把一个未校正、事后的单侧 p=0.045 当成结论，这是本项目反复记录要避免的做法。

已否决：A（见上）；C（这是第 2 阶段目前唯一有效应量的观测，值得一次 40 分钟的确认）；把它并入主判据重算（**不允许——主判据在跑之前定稿，事后把一个次要检验挪进去就是按结果调判据**）。

复查条件：若第三批 seed 上不成立，则记为「五臂实验里的一次未重复的观测」，不得作为结论。若成立，仍受限于 TFN + MOSI 单一骨干与数据集，换骨干需重做。

### 2026-09-04 自适应权重在此配置下是负面结果

裁定：**在 TFN + MOSI 上，梯度变化率调权（窗口 10 与 5）与线性提升权重，均不优于固定均等权重。** 如实记录为负面结果。

依据：seeds 100-119（n=20），BH 6 个检验拒绝 0 个，三个自适应臂的 MAE 均略差于对照。两个竞争解释都被实验排除：

1. **不是功效不足**——MDE 0.0133 覆盖得住这个量级（对比初筛的 0.0759）。
2. **不是策略没执行**——最终权重从均等 0.250 移动到 simsiam 0.541（窗口 10）／0.591（窗口 5）／infonce 0.666（斜坡）。`window=5` 这一臂专为排除此解释而设：调权机会从 1-2 次增加到约 4 次，结果没有变好。

已否决：把「窗口再调小」当作下一步——窗口 10 与 5 的结果没有系统差别，继续缩小是在噪声里找方向，且中位数 24 轮的训练长度本身限制了任何窗口策略能做的事。

复查条件：训练更长（MOSEI 或放宽 patience）时，10 轮窗口才有足够的执行次数，届时应重做。**这条结论绑定 TFN + MOSI + 这四个损失项**，任一改变都需重测。


### 2026-09-05 换 MMIM 骨干，先做协议诊断而不是重跑十四个候选

背景：第 2 阶段在 TFN + MOSI 上得到两条负面结论（自适应权重无效、四项组合未确认）。但有一个前置问题没有答案：**我们这套协议 + 这个数据集，能不能测出一个已知有效的对比损失？** 不回答它，任何负面结论都有一个未排除的竞争解释。

MMIM（Han et al., EMNLP 2021）是唯一可用的参照点：它自带 InfoNCE（CPC）与互信息下界项，**原论文有消融支持**，而且它已经在本仓库里复现并通过验收。它的 `contrast` 开关可以整体关掉这些项。

| 臂 | 内容 |
|---|---|
| `mmim_contrast_on` | MMIM 默认（自带 InfoNCE + MI 项） |
| `mmim_contrast_off` | `contrast=False`，只剩 L1 |

seeds 100-119（n=20），其余协议不变。判据：验证集 MAE/Corr，Welch 单侧 + BH q=0.10，2 个检验。**在运行前定稿。**

依据与读法（这是这条决策的关键，先写下来）：

- **若测得出** → 协议与数据集有能力检出这一类效应，那么 TFN 上那十四个候选的负面结论站得住，问题在候选而不在协议。

已否决：直接在 MMIM 上重跑十四个候选（单次 299s，14×5×20 seed 不可行，且在协议能力未知时跑等于重复 TFN 那一轮的错误）；沿用已入库的 `mmim_mosi`（seeds 42-51）当作 on 臂——跨 seed 批次比较正是 [`investigations.md#seed-batch-variation`](investigations.md#seed-batch-variation) 记下要避免的。

复查条件：本诊断只回答「能不能测出」。它测得出也不意味着 MMIM 上我们那四项会有效；那是另一个实验。

三条先写下来的限定：

1. **λ 只试 0.1。** 单一 λ 的空结果是 λ 特定的，不能读成「这个候选无用」——这正是 MOSI 那轮的教训。若 λ=0.1 上出现结果，再对存活项扫 λ；若全空，则需要扫 λ 才能下结论。成本：单 λ 约 3 小时（15 组 × 5 seed × 约 150s），五个 λ 约 15 小时。
2. **效应量地板保持绝对值 0.01**，不按 MOSEI 更小的方差缩放。它的理由是「小于此的效应无法支撑后续组合步骤」，这个理由与数据集无关。但**显著性会同时按不带地板的形式报告**，所以低于 0.01 的真实效应不会被藏起来——只是不计入「保留」。
3. TFN 在 MOSEI 上的 seed 方差**未实测**，按 LF-LSTM 的 7.9 倍缩放估计 MDE 约 0.005 MAE。**这是估算**，实际控制组方差会在报表里直接给出。

已否决：直接扫五个 λ（15 小时；先用 3 小时拿到基准 λ 上的真实答案更有价值）；把地板按方差缩放（会在看到 MOSEI 方差之后改判据的数值，即使动机正当也应避免；改为并列报告不带地板的显著性）。


### 2026-09-07 淘汰改在 MMIM(contrast=off) / MOSEI 上做，候选按机制减到 4 个，λ 校准到 0.5

背景（用户澄清目标）：第 2 阶段的产出是**造一个损失函数**——组合式或新的对比损失——而筛选只是为组合挑材料。此前我把筛选当成了目标。用户同时指出 **TFN 不是对比学习模型**。

**为什么 TFN 上淘汰不了**：淘汰的前提是能区分「这个损失没用」与「它在这里没机会起作用」。MOSEI + TFN + λ=0.1 下 14 个候选全在 ±0.0035 内、BH 拒绝 0——**没有任何一个产生可测作用**，这淘汰不了任何东西。而且 TFN 的模态向量直接进外积，**它的表征空间不是围绕对比目标构建的**。

裁定：**测试台改为 MMIM 关掉自带对比项，候选放进它腾出的槽位。**

```
对照    MMIM(contrast=False)              n=20，已跑（mmim_diag_mosei_unaligned_off）
处理    MMIM(contrast=False) + 候选        n=10，seeds 100-109
```

三个性质同时满足：是对比学习架构；不会有第二套对比目标与被测者竞争；**该槽位已被证明灵敏**——MMIM 自带的项在这里让验证 MAE 动了 |d|=1.39，且该模型经 `check_mmim_equivalence.py` 证明与 MMSA 逐比特一致。

**候选减到 4 个，按机制而非按排名。** 14 个要 32 小时（820s/seed）。**不能按 TFN 那轮的排名减**——那个排名是噪声，按它减就是重犯 MOSI 那轮的错。每族取一个代表：

| 候选 | 理由 |
|---|---|
| `infonce` | 跨模态配对的标准形式，MMIM 自己的 CPC 属于这一族 |
| `dcl` | 同族但去掉正负耦合，是唯一有文献理由在 batch 32 上work的变体 |
| `vicreg` | 无负样本族，方差项是这批里唯一显式的防坍缩机制 |
| `rnc` | 唯一定义在连续标签排序上、不需分箱的 |

**λ=0.5，是校准出来的而非沿用的。** 各项经尺度归一化后量级≈1，故 λ 即对比部分的绝对贡献。MOSEI 上任务 L1 约 0.53，而 MMIM 自带的 α·nce 约 0.43——**约占任务损失的 80%**。λ=0.1 只占 19%，比唯一产生过效应的那个配置弱四倍，**这很可能是 TFN 那轮什么都没看到的原因之一**。

判据（运行前定死）：验证集 MAE/Corr，单侧检验问「是否变好」、双侧检验问「有无效应」，BH q=0.10 跨 8 个检验。**两个方向都不显著才算淘汰**——这正是本步要产出的结论。有害如实报告，不过滤。MDE 0.0122（n=10，对照 sd 0.0105）小于 MMIM 自带效应 0.0159，分辨力够。

已否决：14 个候选全跑（32 小时）；按 TFN 排名减（噪声）；沿用 λ=0.1（已知比唯一起作用的配置弱四倍）；用 5 个 seed（MDE 0.0183 > 0.0159，答不了）。

**保留的限定**：结果仍是 λ=0.5 特定的，且绑定 MMIM 这一个骨干。

顺带修掉的两处：MMIM 的 `forward` 现在返回 `feature_t/a/v`（加键，惰性——等价测试仍 `0.000e+00`、预测哈希不变）；`ContrastiveModel` 现在转发 `auxiliary_optimizer` 与 `auxiliary_loss`，否则包住 `contrast=True` 的 MMIM 会**静默关掉它的互信息支路**（对本次 `contrast=False` 无害，但是个潜在 bug）。


### 2026-09-07 `dcl` 的正向线索用第二批 seed 确认

背景：MMIM(contrast=off)/MOSEI 的淘汰轮**按判据全部淘汰**（BH 8 检验拒绝 0），但四个候选**全部向好**，`dcl` 达 Δmae +0.0100（原始双侧 p=0.037）、Δcorr +0.0103（p=0.090）。

选项：A 就此当结论／B 用第二批独立 seed 确认／C 视为噪声不追

裁定：**B。**

设计（在任何一次运行之前定稿）：

- 两臂：`dclconfirm_mosei_control`（MMIM contrast=off）与 `dclconfirm_mosei_dcl`（+ dcl，λ=0.5）。
- **seeds 120-139**，与产生线索的 100-119 不重叠。**两臂都重跑**，使对照与候选处于同一批 seed，而不是沿用筛选轮的对照。
- 只两个指标共 **2 个检验**，Welch + BH q=0.10。其余协议不变。
- 成本 40 次运行 × 820s ≈ 9 小时。

依据：该效应量（0.0100）几乎正落在筛选轮的检出线上（MDE 0.0129）——**这正是最需要独立重复的位置**。而本项目在同一位置已经错过一次：TFN/MOSI 上「四项组合优于纯 L1」+0.0131、原始 p=0.045，第三批 seed 上符号翻转（`experiments.md` 确认那节）。n=20 时 MDE 0.0089 < 0.0100，分辨力够。

已否决：A（见上，且原始 p 未过校正）；C（这是本阶段唯一的正向信号，值得一次 9 小时的确认）；沿用筛选轮的对照（对照与候选跨 seed 批次，正是 [`investigations.md#seed-batch-variation`](investigations.md#seed-batch-variation) 记下要避免的）。

复查条件：若不成立，记为「一次未重复的观察」，**`dcl` 不进入组合步骤**。若成立，它是本阶段第一个正向结果，也是组合的第一块材料——但仍绑定 MMIM、MOSEI 与 λ=0.5 三个条件。


### 2026-09-08 跳过余下三项的单项确认，直接测组合

背景：原计划（用户选的「先 1 再 3」中的 1）是把另外三个候选补到 20 seed 逐个确认。**算完功效后这条不可行。**

MMIM(off)/MOSEI 的合并 seed 标准差是 **0.0097**，n=20 的检出线 **0.0078**。三个候选在筛选轮的效应与所需 seed 数：

| 候选 | 筛选轮效应 | 需要 n/臂 | 候选臂单独耗时 |
|---|---|---|---|
| infonce | +0.0054 | ≈41 | 9 小时 |
| rnc | +0.0042 | ≈68 | 15 小时 |
| vicreg | +0.0014 | ≈598 | **136 小时** |

**三个全在 n=20 的检出线以下。** `dcl` 能被确认正是因为它的线索有 +0.0100，n=20 刚好够。按 20 seed 跑这三个，14 小时后只能写「三个都没确认」——那既不是有效也不是无效，**又是一次答不了的实验**，与 MOSI 那轮同型。

裁定：**跳过单项确认，直接测组合。** 组合是任务书要的产出，**且不要求每一项单独显著**——与自适应权重那轮同理。

```
A  MMIM(off)                      已有 20 seed (120-139)
B  MMIM(off) + dcl                已有 20 seed (120-139)
C  MMIM(off) + dcl + vicreg       本轮跑，20 seed
```

**只需跑一条臂**，20 × 820s ≈ 4.6 小时。

三个设计决定：

1. **总 λ 保持 0.5，两项各半。** C 与 B 是**同等总强度**下的比较，回答「把同一预算分给两个机制有无加成」，而不是「加更多对比权重会不会更好」——后者混进来就说不清。
2. **配 `vicreg` 而非 `infonce`，取机制互补。** `dcl` 是带负样本、去耦合的跨模态对比；`vicreg` 是无负样本 + 显式防坍缩。`infonce` 与 `dcl` 同族（也与 MMIM 自己的 CPC 同族），配它等于把一个想法测两遍。`vicreg` 单项确认要约 600 seed，但组合不要求单项显著。
3. **n=20 不是余量而是下限**：n=10 的检出线 0.0113，连 `dcl` 的 +0.0056 都确认不了。

判据（运行前定死）：验证集 MAE/Corr，Welch 单侧，BH q=0.10 跨 4 个检验（2 个比较 × 2 指标）。**C vs A** 问组合是否有用，**C vs B** 问第二个机制是否值得加。

**先写下来的限定**：n=20 对 C-vs-B 的增量只能检出约 0.008 以上，**所以 C-vs-B 的空结果不可读成「第二项无用」**，只是两者都没有证据。

已否决：三项各补 20 seed（见上，功效不可行）；只确认 `infonce`（9 小时，且它与 `dcl` 同族，组合价值低）；提高总 λ 让组合更强（会把「机制加成」与「强度增加」混在一起）。
