# 调查记录

**这个文件存在的唯一目的：不要把同一件事查第二遍。**

每条记录写清楚：问题是什么、试过哪些假设、**哪些被排除了**、结论是什么。被排除的假设和结论一样重要——它们是下一个人不必再走的路。

新增条目时用同样的结构。若某条结论后来被推翻，不要删除原条目，在末尾追加「后续修正」。

## <a id="tfn-acc2"></a>TFN 在 MOSI 上 Acc-2 低于 MMSA 报告值（2026-07-26）

### 现象

10 seed（42-51）验收判定：

| 指标 | 我们 | MMSA | 落后（标准误） |
|---|---|---|---|
| MAE | 0.9585 ± 0.0353 | 0.9473 | +1.0 SE |
| Acc-2(non0) | 0.7742 ± 0.0122 | 0.7908 | **+4.3 SE** |
| Acc-2(has0) | 0.7621 ± 0.0093 | 0.7799 | **+6.0 SE** |
| Corr | 0.6550 ± 0.0125 | 0.6733 | **+4.6 SE** |
| Acc-7 | 0.3474 ± 0.0259 | 0.3446 | −0.3 SE（更好） |
| Acc-5 | 0.3911 ± 0.0334 | 0.3939 | +0.3 SE |

**关键特征：Acc-7/Acc-5/MAE 基本打平，唯独 Acc-2 与 Corr 明显低。** 说明问题不在拟合精度，而在预测的符号分布。差距折合约 11 个样本（656 个非零测试样本的 1.7%）。

### 已排除的假设

| # | 假设 | 如何验证 | 结论 |
|---|---|---|---|
| 1 | 指标实现有别 | 用 MMSA 的 `metricsTop.py` 直接跑我们的预测 | **排除**。逐位一致，差异仅来自它 round 到 4 位小数 |
| 2 | 梯度裁剪 | MMSA 的 trainer 完全不裁剪，我们默认 1.0。跑 10 seed 对照 | **排除为主因**。MAE 从 0.9585 改善到 0.9546（+1.0 SE → +0.8 SE），但 Acc-2 仍低 4.0 SE。**已采纳不裁剪**（保真度） |
| 3 | 轮数上限 | MMSA 用 `while True` + patience 8，无上限；我们上限 40 | **影响极小**。10 个 seed 中仅 seed 50 触顶。**已改为 200 轮**（由 patience 主导） |
| 4 | 文本编码器不同 | 查 MMSA config：TFN 未设 `use_bert`，即用预抽取 768 维特征 | **排除**。与我们一致 |
| 5 | padding 掩码 / 池化方式 | 忠实变体（不掩码 + padded 均值）10→5 seed 对照 | **排除**。忠实变体 Acc-2 0.7701，比我们的默认还低 |
| 6 | 超参不同 | 逐项比对 `config_regression.json` 的 mosi 段 | **排除**。我们用的就是它的值（hidden [128,32,128]、text_out 32、post_fusion 64、dropouts [.3,.3,.3,.5]、bs 32、lr 1e-3） |
| 7 | 预测存在系统性偏移 | 统计预测符号分布 | **排除**。预测为正 45.0% vs 真实 42.2%，漏正 61 / 误正 79，大致平衡，无明显偏置 |

### 结论：差距源自参照值本身的选择偏差

MMSA 的调参流程**按测试集评估候选配置**。`MMSA/src/MMSA/run.py`（commit a94e65d）第 267-270 行：

```python
elif is_tune:
    # use valid set to tune hyper parameters
    # results = trainer.do_test(model, dataloader['valid'], mode="VALID")
    results = trainer.do_test(model, dataloader['test'], mode="TEST")
```

用验证集的那一行被注释掉了。而 `config_regression.json` 中 TFN/MOSI 的每一项超参，都恰好是 `config_tune.json` 搜索空间里的一个取值（`hidden_dims` 四选一、`text_out` 四选一、`post_fusion_dim` 四选一、`dropouts` 四选一）。

**因此其表格数字是「按测试集挑出的超参，在测试集上的成绩」**，带乐观偏差。只用验证集选模型的诚实协议，除非运气好，否则无法稳定匹配这类数字。

这是关于**参照物**的发现，不是我们代码的缺陷。

### 裁定与禁止事项

- TFN 的 **MAE / Acc-7 / Acc-5 判定为复现成功**；Acc-2 / Corr 的差距**已归因**，记录在 `docs/acceptance_status.json`，`check_acceptance.py` 会读取并按 `gap_explained` 处理
- **禁止**为缩小该差距而在测试集上调参——那等于把对方的缺陷一起继承过来
- **禁止**重新调查上表 7 条已排除的假设

### 对后续模型的影响

这个偏差**对所有 MMSA 报告值一视同仁**。后续每个模型都可能出现同量级（约 1-2 个百分点）的系统性差距。处理方式：

1. 先按验收标准判定，差距 > 2 SE 时逐项排查实现差异
2. 排查后仍有差距且模式与本条一致（Acc-2/Corr 低而 MAE/Acc-7 打平），可引用本条归因，但**必须给出该模型自己的排查记录**，不能直接套用
3. 在 `docs/experiments.md` 的对比表中始终标注这一点，避免读者误读成"我们的实现更差"

### 待办

- 量化这个乐观偏差的大小：用我们自己的实现做一次同规模的超参搜索，比较「按验证集选」与「按测试集选」的测试成绩之差。这能把上面的定性归因变成一个数字，也是第 1 阶段结束时值得单独汇报的结果。
